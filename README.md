# TripMemo · 人生记忆地图

把「自己待过的地方」按**停留时长**画在地图上的个人记忆记录网站。

不预设你是"爱旅行的人"——住的学校、长住的出租屋、路过的城市、想去还没去的地方，
都可以放进来。**别人记"去过哪"，这个项目记"待了多久"。**

> 数据存在**云端**（云数据库 + 云存储），**不再存在浏览器里 —— 清缓存不会把数据弄丢**。
> 目前用**匿名登录**：身份凭证保存在浏览器里，所以**换设备 / 换浏览器 / 清缓存后，
> 会以一个新身份进入，看不到之前那份数据**（正式账号体系是后续的事，见 `PRD.md` 4.3）。

## 一、怎么在本地跑起来

### 前提

- 已安装 **Python 3**（用来起一个本地静态服务器；本项目不需要任何第三方依赖）

### 三步启动

```bash
# 1、进入项目目录（就是你现在看到的这个文件夹）
cd 你的项目目录

# 2、启动本地静态服务器（这一条命令会一直占住终端窗口，别关）
python -m http.server 8000

# 3、在浏览器打开
#    http://localhost:8000
```

> **Windows 小技巧**：在文件资源管理器的地址栏里输入 `cmd` 按回车，可以直接在该目录打开终端，
> 省得手动 `cd`。

**成功现象**：终端输出 `Serving HTTP on ... port 8000`，浏览器里出现中国地图和左上角的搜索框。

**停止服务器**：回到终端按 `Ctrl + C`。

> **为什么不能直接双击 `index.html`？**
> 直接打开用的是 `file://` 协议，和 `http://localhost` 是两套环境。
> 用本地服务器更接近真实环境，也能避免一系列奇怪的问题。

**端口 8000 被占用的话**：换成 `python -m http.server 8001`，浏览器地址相应改成 `http://localhost:8001`。

## 二、首次使用：配置高德地图 Key

地图由**高德地图 JS API** 提供，需要一个 Key。

### 1. 申请 Key

1. 打开 <https://lbs.amap.com>，注册账号并完成**实名认证**
2. 控制台 → **应用管理 → 我的应用 → 创建新应用**
3. 在该应用下点 **「添加 Key」**：
   - **服务平台：必须选「Web端（JS API）」**（选错会导致地图加载失败）
   - 域名白名单：**留空**
4. 复制两样东西：**Key** 和 **安全密钥（securityJsCode）**
   > JS API 2.0 **两个都要**，只填 Key 地图不会显示。

### 2. 填进配置文件

把 `config.example.js` 复制一份，命名为 **`config.js`**，然后填入两串值：

```js
window.TRIPMEMO_CONFIG = {
  amapKey: '你的 Key',
  amapSecurityCode: '你的安全密钥'
};
```

> `config.js` **已被 `.gitignore` 挡住，不会被提交到 GitHub**。
> 另外提醒：前端代码里的 Key 在浏览器里是能看到的（按 F12），
> 所以真正的防线不是"藏起来"，而是**域名白名单**和**用量监控**。
> 个人开发者免费额度是 1 万次/月，本项目远用不到。

## 三、怎么用

| 功能 | 怎么做 |
|---|---|
| **添加地点（点击）** | 点地图上任意位置 → 在弹窗里填写 |
| **添加地点（搜索）** | 在搜索框输入地名（如「华中科技大学」）→ 从下拉里选一个 → 自动定位并填好名称与城市 |
| **查看某个地点** | 点地图上的点、时间轴卡片，或地点列表里的条目 |
| **修改 / 删除** | 在查看态点「编辑」 |
| **按类型筛选** | 地图左上角的「全部 / 长期居住 / 短期停留 / 旅游 / 想去」 |
| **设定主城市** | 输入城市名 → 点「设定」。地图上会出现锚点，并从它向其他城市连线（**线越粗 = 在那座城市待得越久**） |
| **备份数据** | 点右上角「导出 JSON」 |

### 关于「想去」

「想去」是**还没去过**的地方，所以它有三条特殊规则：
显示为最小的点、悬停显示「下一站」、**不进入时间轴、也不参与连线**。

## 四、你的数据存在哪（很重要）

数据存在**云端**：地点与回忆写进 **CloudBase 云数据库**，照片写进**云存储**。
每个访客用**匿名身份**登录，数据按 `ownerId` 隔离 —— **只有你自己看得到**。

⚠️ **这意味着两件事**：

- ✅ **好处**：数据不再只活在这台浏览器里，**清浏览器缓存不会把数据弄丢**（云端还在）
- ⚠️ **边界**：身份凭证（匿名会话）存在浏览器里 —— **换电脑 / 换浏览器 / 清缓存后，
  会以一个新身份进入，看不到之前那份数据**。因为这层限制，
  **「导出 JSON」在账号体系做出来之前仍然是你的保险绳**，建议定期备份。

## 六、技术栈

- **原生 HTML / CSS / JavaScript**（不用框架、不用构建工具）
- **高德地图 JS API**（地图显示、搜索选点）
- **腾讯云 CloudBase**：云函数（HTTP 函数，后端接口）+ 云数据库（地点 / 设置）+ 云存储（照片）
- **匿名登录**（`@cloudbase/js-sdk`）：给每个访客一个独立身份，数据按 `ownerId` 隔离

## 七、发布前检查（上线前跑一遍）

改完东西、准备发布/部署之前，在项目根目录跑：

```powershell
python verify-project.py
```

它会跑 **14 项自动检查**，逐项打印 `PASS` / `FAIL` / `SKIP` + **证据行**（不是干巴巴一句"失败"）。
**任何一项 FAIL 都不要发布。**

**查哪些东西**（全部来自本项目真实踩过的坑）：

| 类别 | 检查项 |
|---|---|
| 安全 | 硬编码密钥、Git 历史里的 `config.js`、`.gitignore` 覆盖 |
| 代码 | 11 个 js 文件的语法（`node --check`）|
| 文档 | 有没有"数据存在浏览器里"这类过时说法 |
| 线上 | 关键文件是否都 200、⭐ **`?v=` 本地与线上是否一致** |
| 后端 | 云函数路由可达、接口鉴权（**读**和**写**两侧）、跨域、环境变量 |
| 数据 | ⭐ **数据库读写端到端**（写 → 读回 → 删 → 确认删干净）|

**读输出的三条规矩**：

- `[PASS]` 过了 ｜ `[FAIL]` **先修再发布** ｜ `[SKIP]` **不是问题**
- ⭐ **`SKIP` 表示"没网/连不上线上"** —— 联网后重跑即可，**它不算失败**（不然没网时满屏红，这检查器就没人信了）
- 有 FAIL 时**退出码是 1**，全绿是 **0**（想接 CI 时能用上，现在没接）

**怎么修 FAIL**：见 `TripMemo-发布前检查清单-20261011.md`，每项都写了「执行命令 / 通过标准 / 失败怎么修」。

> ⭐ **怎么确认这个检查器本身可信**：**故意弄坏一项，看它会不会喊。**
> 例：把 `index.html` 里任一 `?v=72` 改成 `?v=71` → 第 8 项应该 FAIL 并报出「本地 ?v=71 ｜ 线上 ?v=72」。
> 改完记得改回来。**一个永远报 PASS 的检查器，比没有检查器更危险** —— 它给人"我检查过了"的错觉。

> ⚠️ 数据库那项（第 13 项）用**独立的匿名身份**跑，**不会碰你自己的数据**；
> 而且每次跑之前会先清理上次可能的残留。
